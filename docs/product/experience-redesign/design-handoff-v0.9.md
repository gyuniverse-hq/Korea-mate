# KoreaMate · D 메인 고충실도 기준 시안 및 HTML 구현 v0.9

> **상태:** 개인 UX·디자인 시연 / 팀 미확정  
> **작업 기준일:** 2026-10-17  
> **작업 브랜치:** `docs/koreamate-experience-redesign`  
> **선행:** 서비스 경험 구조 v0.5 → 디자인 방향 v0.6 → 메인 A/B/C v0.7 → D·4브랜드 실험 v0.8

## 1. 이번 작업에서 무엇을 바로잡았나

v0.8의 4가지 테마 HTML은 브랜드 색과 그래픽을 바꾸는 실험으로만 보존한다. 사용자가 긍정적으로 평가했던 **초기 D 이미지 3장의 사진 중심 몰입감, 메인의 정보 위계, 전문 기능의 가시성**이 HTML 과정에서 사라졌기 때문이다.

**v0.9는 하나의 고충실도 D 메인 기준 화면을 먼저 선정·정리하고, 그 화면 한 장만 반응형 HTML로 구현한다.** Kravel·Beauty·Season 등의 전문 기능 전체를 억지로 같이 개발하지 않는다.

## 2. 이 화면이 보여줘야 하는 제품의 정체성

- **첫인상:** 한국 여행과 K-Culture를 발견하고 싶은 마음이 드는 풍부한 사진과 간결한 메시지
- **즉시 도움:** Ask·Scan·For You·My Korea Plan·Korea 101로 곧바로 들어갈 수 있는 실제 UI
- **발견과 큐레이션:** 지금 한국에서 발견할 이야기(음식·여행·뷰티·이벤트·생활문화)를 탐색
- **전문 경험:** Kravel·K-Beauty·K-Season·GG Korea·K-Class의 대표 비주얼과 직접 진입점
- **서로 연결되는 결과:** 저장한 관심사가 나중에 여행 계획·행사 검증·Plan B에 활용되는 구조(기획 방향; 아직 실제 연동 전)

## 3. 시각 디자인 기준

| 항목 | 기준 |
|---|---|
| 히어로 | 서울 야경·N서울타워·도시 감성, 깊은 네이비 오버레이, 상단 투명 내비게이션 |
| 대표 문구 | “한국을 더 가까이, 더 특별하게”와 작게 보조하는 KoreaMate 설명 |
| 상호작용 중심 | 하얀 검색 필드, 카메라·음성 입력, 상황형 빠른 동작 |
| 콘텐츠 | 다채로운 사진 자체가 주인공, 태그·제목은 하단 명확하게 |
| 전문 기능 | 메인에서 발견하되, 실제 전문 화면은 각자 다른 구조로 설계할 예정 |
| 반응형 | 모바일에서 Ask와 Scan 접근성 우선, 스토리는 수평 탐색 |
| 일관성 | KoreaMate 브랜드 네비게이션, 저장 경험, 공통 도움 호출 방식 공유 |

**사진 처리 원칙:** 생성 시안의 사진 영역을 **별도 이미지 파일로 가공하고**, 텍스트·입력창·버튼·저장 액션은 HTML/CSS/JavaScript로 독립 렌더링한다. 완성된 AI 화면 이미지를 전체 배경으로 넣어 클릭만 덧씌우는 방식은 사용하지 않는다. 현재의 개별 카드 사진도 **시연용 생성 자산**으로, 최종 공개 전에 출처·표현 적합성·선명도를 재검토한다.

## 5. 클릭하여 체험할 수 있는 범위

- **진입 기능:** Ask / Scan / 음성 안내 / For You / 여행 계획 / Korea 101
- **문화 탐색:** 카테고리 필터, 콘텐츠 상세 안내(시연), 하트 저장·해제, 저장 내용 확인
- **전문 기능:** 각 기능 카드에서 기능의 고유 가치 확인(시연)
- **보장하지 않는 기능:** 실제 LLM 답변, 이미지 업로드·인식, 얼굴 AR, 행사 운영정보·가격/예약 검증, 실시간 여행 일정 계산
- **저장:** 브라우저 실행 중 임시 상태만 관리하며, 서버 전송·영구 저장은 없음

버튼이 실제 기능을 실행하지 않는 경우 **시연용 안내 팝업**이 열리고 기능 구현을 가장하지 않는다.

## 7. 시안과 HTML 사이에 남은 디자인 차이

1. **타이포그래피:** 생성 시안의 손글씨 느낌을 그대로 복제하지 않았다. 실제 읽을 수 있는 한국어 시스템 글꼴을 적용했으며 브랜드 타이포그래피는 추가 결정 필요.
2. **사진의 디테일:** 시연 이미지를 편집해 분리한 일부 카드 사진은 생성 시안만큼 선명하지 않다. 전용 고해상도 이미지 제작/선별 필요.
3. **오른쪽 카드·여백:** 실재하는 반응형 레이아웃으로 조정하면서 생성 시안과 몇몇 여백·비율이 다르다.
4. **기능 범위:** 메인 UI 재현이 목적이므로 전문 상세 기능은 뒤에 구현한다.
5. **데이터:** 카드의 시즌·추천 내용은 예시. 실제 추천·운영 정보 검증 전에 실사용 서비스의 트렌드라고 말할 수 없다.
