# 04 · 디자인 평가 기준 · 결과 양식

> 결과는 **전문가의 휴리스틱(heuristic) 평가**다. 실제 사용자 테스트나 사용자의 선호도 통계로 해석하지 않는다.

## 1. 평가 목표와 가중치

정량 점수는 토론을 돕는 보조 수단일 뿐이며, 낮거나 높은 점수보다 **문제의 사용자 영향과 개선 우선순위**가 중요하다.

| 평가 축 | 가중치 | 핵심 검토 질문 |
|---|---:|---|
| A. 제품 정체성 전달 | **20점** | 5초 내 'KoreaMate가 왜 필요한지' 이해되는가? 단순 여행·뷰티 광고로 보이지 않는가? |
| B. 시각 디자인 완성도 | **20점** | 사진·타이포·색·그리드·여백·카드 품질이 일관되고 매력적인가? 양산형/저품질 느낌은 없는가? |
| C. 정보 위계·진입 명확성 | **20점** | Ask/Scan, 문화 발견, 추천, 전문 기능 중 우선 행동이 명확한가? |
| D. 전문 기능의 독립성과 융합 | **15점** | Kravel/Beauty/Season 등의 고유한 경험이 보이며, KoreaMate의 존재감을 해치지 않는가? |
| E. 모바일 반응형 UX | **10점** | 첫 화면, 터치, 스크롤, 하단 바, 카드 탐색에서 마찰이 적은가? |
| F. 상호작용·접근성 | **10점** | 버튼 상태/역할, 입력/피드백, 아이콘 이해도, 대비, 키보드/스크린리더 설계가 합당한가? |
| G. 정보 신뢰·실현 정직성 | **5점** | 현재 콘텐츠·실시간 행사·AI 기능의 시연 상태가 명확히 표시되는가? |
| **합계** | **100점** | 숫자보다 *왜* 그 점수인지, 무엇을 바꿔야 하는지 중요 |

각 축을 **1~5점(1 매우 미흡 / 3 보통 / 5 우수)**으로 주고, `가중치 × 평점 ÷ 5`로 환산할 수 있다. **이미지·동작을 실제로 보지 못했다면 해당 축에 무리하게 점수를 넣지 말고 '평가 보류'**로 기록할 것.

## 2. 문제를 기록하는 방식

| 열 | 기입 예시 |
|---|---|
| 화면·영역 | `HOME-001 / H02 Ask 검색창 / 모바일 390px` |
| 현재 관찰 | '카메라 아이콘과 메인 전송 버튼의 우선순위가 모호함' |
| 문제 성격 | Visual / IA / Interaction / Accessibility / Content / Product-fit |
| 사용자 영향 | '첫 방문자가 사진 업로드의 결과를 예측하지 못함' |
| 우선순위 | `P0: 사용 불가/오해 위험` · `P1: 핵심 경험 약화` · `P2: 다듬으면 개선` |
| 수정 제안 | '문구/상태를 분리하고 모바일 예시 화면을 추가한다' |
| 확인 방법 | '신규 사용자 5초 테스트 / 화면 비교 / 접근성 점검' |

## 3. 실제 평가자에게 부탁할 필수 산출물

1. **한 문단 총평:** 출시 가능한 느낌인가? 브랜드가 특별한가? 디자인이 싸구려/데모처럼 보이는 근본 원인은?
2. **가장 먼저 고쳐야 할 문제 상위 5개:** 위치, 증거, 사용자 영향, 우선순위, 구체적 수정.
3. **유지할 요소 3개:** 단순 취향이 아니라 제품 목표에 기여하는 이유.
4. **PC 대 모바일 차이:** 각각의 첫 뷰포트에서 느끼는 문제와 장점.
5. **메인에 없는 전문 경험을 어떻게 보여줄지:** Kravel, K-Beauty, K-Season의 차별적 표현 가이드.
6. **수정 제안의 분류:** 당장 HTML 조정 가능 / 이미지·타이포 자산 재제작 필요 / IA 또는 서비스 기획 변경 필요.
7. **최종 권고:** 현 방향 개선 또는 다른 디자인 방향 전환, 그 판단의 근거.
8. **확인되지 않은 사실:** 화면을 직접 못 봤거나 동작/사용자 조사 없이 추정한 부분을 별도 명시.

## 4. 평가가 까다로워야 하는 이유

이전 제작물은 몇 번이나 '메인은 예뻐 보이지만 실제 HTML은 획일적이다'라는 문제를 반복했다. 따라서 좋은 평가라면 **디자인 목표 이미지의 완성도만 보고 합격시키는 것이 아니라 실제 브라우저 결과를 우선**해야 한다.

또한 KoreaMate의 제품 목적은 '기능이 많다'가 아니다. Scan·Ask와 Discover가 서로 자연스럽게 공존하면서, 각 전문 기능에서 실제로 풍부한 경험을 할 수 있는지 의심하고 확인해야 한다.

## 5. 검토 후 의사결정용 초안 표

| 결정 후보 | 선택지 | 평가 의견·근거 | 결정 상태 |
|---|---|---|---|
| Hero 이미지 방향 | 현재 유지 / 다양한 한국 문화 사진 재선별 / 완전히 교체 | _(평가 후 작성)_ | 미정 |
| 색상 시스템 | 네이비·핑크 개선 / 다른 시각 방향 제안 | _(평가 후 작성)_ | 미정 |
| Ask/Scan 배치 | 중앙 검색 / Scan 우선 / 발견 우선 | _(평가 후 작성)_ | 미정 |
| 전문 경험 노출 | 현재 카드 보강 / 대표 체험 시연형 / 매거진형 | _(평가 후 작성)_ | 미정 |
| 모바일 우선 액션 | Ask / Scan / Discover | _(평가 후 작성)_ | 미정 |
| 실제 데이터 표시 | 시연 워터마크·기간·출처 정보 규칙 | _(평가 후 작성)_ | 미정 |

> **팀원 기능의 존치·배제나 구현 책임은 평가자가 대신 결정하지 않는다.** 선택지와 비용·장단점을 제시하고 팀에서 최종 결정한다.
