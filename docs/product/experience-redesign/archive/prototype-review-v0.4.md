## 2. 메인 역설계 기준

KoreaMate의 원래 사용자 문제 세 가지는 유지한다.

1. **모르니까 못한다:** 한국을 처음 방문하는 사람이 한국 생활문화·서비스·준비물을 스스로 검색할 수 없어 놓치는 경험을 줄인다.
2. **알아도 하기 어렵다:** 언어·운영 조건·결제·예약·이동·현장 문제 때문에 행동하지 못하는 상황에서 다음 단계를 돕는다.
3. **정보가 흩어져 있다:** 콘텐츠 발견부터 실제 행동까지 사용자가 서로 다른 앱의 정보를 직접 연결하는 부담을 줄인다.

이 목적에 따라 메인에는 (A) 질문/사진/SNS, (B) Korea Pulse, For You, Korea 101, (C) Kravel·Beauty·Season 등 전문 체험, (D) My Korea & Help Me Now를 배치한다. 전문 기능으로 **직접** 들어가는 경로도 보존한다. KoreaMate AI Mate를 매번 통과해야 하는 강제 구조가 아니다.

## 3. 필수 시연 A: See it → Live it → Plan B

- 시작: `발견하기` → `봤던 것을 직접 해보고 싶다면` 또는 상단 `찍고 물어보기`.
- 사용자가 보는 샘플: **성수 사운드룸 팝업 X** 가상 SNS 포스터 (시연 날짜 2026.10.10~15).
- `시연 분석하기`: 샘플의 종료 시점과 여행일(기본 2026.10.22)을 비교해 **현재 계획으로는 방문할 수 없다는 시연 결과** 제공.
- `대안으로 일정 조정`: K-Season 대안으로 만든 가상 성수 스토리 팝업 선택.
- `변경안 적용하기`: 기존 가상 서울 하루 코스에 행사를 추가하고 My Korea에 반영.
- **융합 가치를 드러내는 요소:** 단순한 사진 번역이 아니라 사용자 목적을 보존하면서 실패 이유를 설명하고 새 행동으로 복구.
- **남은 검증:** 실제 이미지 내용 인식, 공식 팝업 일정 및 출처, 출입/예약 조건, 대안 추천 정확도, 이동시간.

> 파일 업로드는 화면에서 사진을 **로컬 미리보기**할 뿐 실제 이미지를 분석하지 않는다. 분석 내용은 고정된 가상 시나리오다.

## 4. 필수 시연 B: Kravel → K-Season → Kravel (A→B→A)

- 시작: `여행 만들기` → 작품, 여행일, 교통방식 선택 → 코스 만들기.
- 초기 코스: 10:00 캠퍼스 → 14:30 연남동 카페 → 18:30 남산 노을 (모두 도식 예시).
- `K-Season에서 찾기`: Kravel의 여행 날짜를 유지한 채 시연 행사 목록으로 이동.
- `내 일정과 비교`: 14:30 성수 스토리 팝업을 추가할 때 원래 연남동 일정과 충돌하는 이유 설명.
- **변경 전/후:** 오후 방문지 일부를 성수 중심으로 바꾸고 14:30 행사를 포함한 새로운 코스 제안.
- `변경안 적용하기`: 승인한 결과가 다시 Kravel의 시간표·도식 지도에 반영됨.
- `원래 코스로`: 행사 반영을 되돌림.
- **융합 검증 질문:** K-Season 없이도 행사 기간과 시간을 정확히 반영할 수 있는가? Kravel 없이 같은 사용자 조건을 적용해 새 여행 계획을 만들 수 있는가?
- **남은 검증:** 실제 POI 좌표/촬영지 근거, 행사 갱신, 이동시간, 예산/예약 제한/시간 충돌 규칙.

## 5. 필수 시연 C: K-Beauty 독립 체험 → 선택적 연결

- 시작: `K-Beauty` → Natural/Rosy/Peach/Mauve 룩 선택.
- 화면: 모델의 동일 사진에 서로 다른 **이미지 필터**를 적용해 전후 비교 슬라이더와 강도 변경을 시연. 실제 얼굴 랜드마크 기반 AR이 아님.
- 제품: 립/블러셔/아이섀도 구성 예시·Look-to-Cart 목록.
- 선택 1: `이 룩 저장하기` → 뷰티 기록만 남기고 여행 기능은 사용하지 않음.
- 선택 2: `한국 방문 후보로 저장` → My Korea에 매장 방문 후보 추가. 실제 재고, 가격/판매 여부 확인 전.
- **융합 검증 질문:** 여행 연결을 제거해도 뷰티 체험 자체가 충분히 매력적인가? 연결을 선택했을 때 실제 행동으로 나아가는 데 도움이 되는가?
- **남은 검증:** 실제 AR 합성 정확도, 제품/룩 매핑, 사진 동의/처리, 공식 판매처·재고·예약 확인.

## 6. 팀원의 전문 기능은 그대로 보존

- **K-Class Curator:** 학습자 모드에서 자체 제작 예문 기반 한국어 퀴즈, 튜터 모드에서 수업안 시뮬레이션. 공식 클립·실제 난이도 분류·저작권 검증은 미연결.
- **GG Korea:** Fan 트랙은 응원팀 중심, Pro Path 트랙은 대회 자격 및 연습 준비 중심으로 분리. 경기·대회 API 미연결.
- **K-Food Market Curator:** 관광객 음식 안내 기능으로 왜곡하지 않고 **한국 식품기업 해외시장 분석 B2B**로 분리. 국가 변경/가상 경쟁상품 그래프 시연. 수치는 임의 설명용.
- **여행자 음식/Scan Anything:** 현장 메뉴·매운맛 이해·직원에게 보여줄 문장 기능의 예시. K-Food Market과 다른 사용자·목적임을 명시.

## 7. 실제 브라우저 점검 결과

검증은 브라우저에 **단일 HTML 내용을 직접 로드**해 수행. 웹 탐색 정책이 적용된 테스트 환경에서 URL 접근이 제한되어 별도 서버 응답 검사 대신 자바스크립트·DOM·시각 화면 동작을 확인했다.

|---|---|

| Kravel → K-Season → 비교 → 적용/되돌리기 | 통과 |

| K-Class/ GG / B2B 영역 탭·시연 상호작용 | 통과 |

## 8. 다음 설계에서 확인할 판단 질문

1. 사용자가 **KoreaMate 자체**를 이용하고 싶은 이유를 첫 화면 10초 안에 이해하는가?
2. 원래 KoreaMate의 발견/현장 도움 기능을 사용한 뒤 **무엇을 할 수 있게 됐는지** 이해하는가?
3. Kravel과 K-Season을 합치면 단순 메뉴 이동보다 **더 좋은 코스 결과**가 나온다고 느끼는가?
4. K-Beauty를 독립 체험하고 싶다는 기대가 있고, 여행 연결을 **강제당한다고 느끼지 않는가?**
5. 전문 기능 원안(학습자/튜터, 팬/프로, B2B)의 문제와 대상 사용자가 훼손되지 않았는가?
6. 실제 데이터와 연결해도 날짜·영업·예약·동선 조건의 불확실성을 정직하게 표시할 수 있는가?

**권장 다음 작업:** 팀원에게 HTML을 공유해 대표 과제를 직접 수행하게 하고 관찰을 기록한다. 시연 만족도와 기능 간 추가 가치가 확인된 뒤 공통 데이터 계약(`TripContext`, `ExperienceCandidate`, `ActionProposal`, 출처·검증시각·승인 상태)을 확정하고 실제 API/AI 연동 범위를 결정한다.
