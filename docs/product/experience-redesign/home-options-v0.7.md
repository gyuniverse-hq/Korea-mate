## 왜 세 가지를 비교하나

이전 HTML(v0.1~v0.4)의 반복 문제는 기능을 과다 보유했기 때문이라기보다 **카드/설명/AI/이미지의 시각적 우선순위가 뒤섞여, 사용자 경험과 전문 서비스 고유 가치가 동시에 희미해진 것**이다. 메인 화면의 핵심 질문을 세 가지로 나눠 각각 한 화면에서 검증한다.

| 방향 | 첫 행동 | KoreaMate 가치 | 전문 기능 노출 | 위험 |
|---|---|---|---|---|
| **A. 문화 발견형** | 콘텐츠 탐색 → Ask 또는 Scan | For You, Korea Pulse, Korea 101, 몰라서 못하던 경험 발견 | 편집형 주요 콘텐츠 + 직접 진입 영역 | 메인이 관광 매거진처럼만 보이고 전문 기능이 뒤로 밀릴 수 있음 |
| **B. 상황 해결형** | 사진 / SNS / 질문 | Vision AI, See it → Live it, Plan B, Help Me Now | 문제 해결에 필요할 때 연결 | 챗봇·업무용 도구처럼 보이고 문화 발견의 설렘 약화 |
| **C. 전문 체험형** | Kravel·Beauty·Season 등의 대표 체험 시작 | 필요할 때 AI Mate 호출 | 가장 선명하게 노출 | 여러 서비스의 모음처럼 보이고 KoreaMate 자체의 정체성 약화 |

## 실제 시안의 핵심 차이

### A. 문화 발견형
- 큰 문화 비주얼과 감성적 문구. 사용자가 아직 모르는 경험을 먼저 본다.
- Ask / Scan을 첫 화면에 함께 둬 원래 문제 해결 능력이 묻히지 않게 한다.
- 본문에서는 **For You / New to You / Korea Pulse**를 서로 다르게 편집한다.
- '더 깊게 경험하기'로 전문 기능 직접 진입을 제공한다.
- 문제: 현재 예시에서는 뷰티 사진 비중이 과도하여 모든 관심사를 대표하지 못할 수 있다. 콘텐츠 균형 검토 필요.

### B. 상황 해결형
- 큰 질문·카메라·SNS 공유 진입이 최우선.
- 인식 후보 → 확인 가능한 운영 조건 → Plan B 제안의 3단계가 시각적으로 명확.
- 전문 결과(K-Season, Kravel)는 독립 버튼보다 **하나의 사용자 문제를 해결하는 근거/행동**으로 드러난다.
- 문제: 실제 서비스를 처음 보는 사용자는 문화 발견 서비스인지 모르고 범용 AI 채팅 도구로 인식할 위험.

### C. 전문 체험형
- Kravel은 여행 코스, K-Beauty는 룩 체험, K-Season은 행사 탐색이라는 **서로 다른 결과/조작**을 표지에서 보여 준다.
- K-Class / GG Korea / K-Food 등에도 직접 진입.
- AI Mate는 별도의 보조 도구로 노출.
- 문제: '왜 하나의 KoreaMate여야 하는가?'를 전문 서비스 목록만으로 설명하기 어렵다.

## 권장 조합안 — 결론 확정 전 제안

**메인: A의 문화 발견 구조 + B의 Ask·Scan을 확실한 입구로 + C의 전문 경험 갤러리**를 추천한다. 화면을 단순 합쳐서 세로로 길게 만들자는 뜻이 아니다.

- 메인 첫 화면: 문화의 설렘을 먼저 보여주되 Ask·Scan 즉시 실행.
- 첫 스크롤: For You / New to You / Korea Pulse 중 사용자에게 의미 있는 내용을 엄선.
- 체험 진입: 각 전문 분야의 '**대표 조작 순간**'이 명확한 편집형 섹션(6개 동일 카드 반복 금지).
- 현장 도움: 사용자의 위치/상황이 허락될 때 B와 같이 문제 해결을 우선.
- 전문 화면: C와 같이 콘텐츠/지도·룩·캘린더·영상이 실제 주인공.
- 맥락 연결: Kravel → K-Season → 변경 전후 일정 승인 등 결과 개선을 보여주되 억지 연결을 강제하지 않는다.

## 실제 화면 설계에서 해결해야 할 5개 문제

1. 메인 첫 화면에서 Ask와 Scan 중 무엇을 1차 강조할 것인가? 사진/SNS 사용 빈도 조사 필요.
2. A의 문화 콘텐츠가 관광 광고처럼만 보이지 않게 데이터 출처·시점·개인화 이유를 언제 보여줄 것인가?
3. Kravel·Beauty·Season의 대표 기능을 메인에서 어디까지 미리 조작하게 할 것인가?
4. 모바일 첫 화면에서 히어로 이미지와 행동 버튼 중 무엇을 접지 않고 보여줄 것인가?
5. 첫 버전에서 시연 데이터와 검증된 운영 정보를 구분할 시각 언어는 무엇인가?

## 디자인 QA (이번 v0.7)

- ✅ PC 3방향 레이아웃, A 모바일 변형, A/B/C 전환 버튼 생성.
- ✅ HTML 단일 파일(이미지 내장), 브라우저에서 다운로드 후 열기 가능.
- ✅ 테스트 렌더링에서 JS 오류 없음, 전체 가로 넘침 없음.
- ⚠️ 화면 속 문화/사진 소재는 **이전 시연 이미지를 사용한 임시 배치**이며 실제 장소·운영·예약 정보가 아니다.
- ⚠️ 디자인은 **구조 비교용 5단계 와이어프레임**. 직접 돌아가는 Kravel·AI·AR·행사 필터를 구현한 것이 아니다.
- ❌ 실제 사용자 과제 평가, 디자인 선택 합의, 고충실도 최종 시안은 아직 진행하지 않았다.

## 사용자에게 보여주고 설명하는 방식

1. A/B/C를 순서대로 화면으로 제시한다.
2. 각 안의 **첫 행동 / 강점 / 약점 / KoreaMate 원안 충실도 / 팀원 아이디어 가시성**을 설명한다.
3. 선호도와 변경 제안을 받은 뒤 방향을 확정하거나 혼합안 D를 만든다.
4. 디자인 방향이 정해지면 메인 + Scan/Help + Kravel + K-Beauty + Season의 고충실도 시안을 별도로 제작한다.

**팀원 아이디어 도입/배제, 브랜드 디자인 및 구현 범위는 아직 확정하지 않았다.**
