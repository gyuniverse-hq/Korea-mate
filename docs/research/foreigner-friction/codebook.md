# 코드북 · 불편 사례 단위와 분류 규칙 v1.0

**분류 단위:** `한 사용자 × 한 목표 × 한 막힌 단계(또는 성공 경험)` 1행. 동일 글에 서로 다른 사건이 있으면 case_id는 별도, source_id는 동일.

## 1. 원천 및 증거 필드

| CSV 열 | 설명 | 입력 규칙 |
|---|---|---|
| `case_id` | 사건 고유 ID | `KM-FR-001` 형식, 중복 불가 |
| `source_id` | 원천 식별자 | 같은 게시글의 다른 사건에는 같은 ID 사용 |
| `source_platform` | 최초 게시 플랫폼 | `Reddit`, `PTT`, `Yahoo知恵袋` 등 |
| `source_url` | 원문 확인 링크 | `https://`로 시작하는 URL; 개인정보 포함 추적 파라미터 제거 |
| `post_date` | 게시일 | ISO `YYYY-MM-DD`. 실제 사건 발생일과 혼동하지 않음 |
| `source_language` | 원문 언어 | `en`, `ja`, `zh-Hant`, 추가 언어는 코드북 갱신 후 추가 |
| `evidence_type` | 주장의 강도와 작성자 위치 | 아래 유형표 참조 |
| `collection_depth` | 읽고 코딩한 자료의 범위 | 현재 `post_or_excerpt`, 이후 `full_thread`, `video_checked`, `comment_checked` 등 |
| `pilot_status` | 검수 상태 | `INITIAL_SINGLE_CODER` → `DOUBLE_CODED` → `ADJUDICATED` |
| `collector_note` | 관측 경계·맥락 | 제삼자 개인 정보나 근거 없는 사용자 속성 입력 금지 |

`evidence_type`의 규칙은 다음과 같다.

| 값 | 정의 | 예 |
|---|---|---|
| `FIRSTHAND` | 본인이 수행·실패·완료했다고 진술 | 결제 3DS 후 빈 화면을 봤다고 씀 |
| `COMMENT_FIRSTHAND` | 댓글 작성자가 본인 경험으로 진술 | 여러 지도 앱을 번갈아 사용했다고 댓글에 씀 |
| `QUESTION` | 발생·예상 여부 불명확한 우려·정보 요청 | 해외카드가 될지 출발 전 질문 |
| `SECONDHAND` | 타인의 사례 또는 외부 기사 전달 | 친구가 막혔다고 소개 (시범에는 별도 추출 없음) |
| `GUIDE` | 공식 아닌 정보 안내 또는 크리에이터 팁 | 영상 설명의 앱 추천 (사건으로 집계하지 않음) |

**중요:** 질문의 제목에 “안 돼요”가 있어도, 작성자가 이미 실제로 시도하고 막힌 것을 설명하면 `FIRSTHAND`로 코딩할 수 있다. 반대로 ‘한국 번호가 필요하다고 들었다’는 질문은 `QUESTION`이다.

## 2. 사건·결과 필드

| CSV 열 | 설명 | 입력 규칙 |
|---|---|---|
| `travel_stage` | 게시글에서 확인되는 사용자 시점 | `BEFORE`, `IN_COUNTRY`, `AFTER`, `UNKNOWN` |
| `user_goal` | 사용자가 하려던 실제 일 | ‘지도 앱’이 아니라 ‘방문할 장소의 위치 찾기’처럼 행동으로 작성 |
| `blocked_step` | 실제로 멈췄거나 불확실한 단계 | ‘인증번호 수신’, ‘결제창 표시’, ‘행사 운영 여부 판단’ 등 |
| `primary_barrier` | 가장 직접적인 장애 유형 | 아래 코드 12종 |
| `secondary_barrier` | 복합 원인 후보 | 없거나 확인 불가하면 빈 칸 |
| `case_kind` | 사건의 성격 | `FRICTION`, `CONCERN`, `POSITIVE`, `MIXED` |
| `reported_outcome` | 당사자 기록으로 확인되는 상태 | `UNKNOWN`, `FAILED`, `BLOCKED`, `PARTIAL`, `WORKAROUND`, `SUCCEEDED` |
| `impact` | 작성자가 암시/확인한 영향 | `UNKNOWN`, `ANTICIPATED`, `BLOCKED`, `DELAYED`, `EXTRA_STEPS`, `NONE`, `LOW` |
| `summary_ko` | 공개 원문의 짧은 한국어 의역 | 한두 문장, 사실·질문·의견을 구분. 원문을 대량 번역·전재하지 않음 |
| `verification_needed` | 반드시 확인할 현재 조건 | 원본 서비스 정책·자격·운영시간·문항·이용약관 등 |

`case_kind`는 **불편의 직접 관측과 걱정만 있는 자료를 집계 단계부터 분리**하려는 용도다. `POSITIVE`는 불편이 없거나 유용한 해결을 경험한 자료를 포함하되, 개선 효과가 입증됐다는 의미가 아니다.

## 3. 주 장벽 코드와 경계 사례

| 코드 | 정의 | 예 | 혼동 방지 |
|---|---|---|---|
| `IDENTITY` | 회원·전화번호·국내 본인인증 또는 로그인 자격·계정 차단 | 예약 마지막 단계 한국 통신사 인증, 지도 계정 차단 | 예약 화면 안에서 일어났더라도 직접 장애가 본인확인이면 IDENTITY |
| `PAYMENT` | 카드 승인·3DS·결제 정보 입력·결제 뒤 상품 미수령 | 해외 카드 인증창 멈춤 | 가격·정책을 이해하지 못하는 정보 요청과 다름 |
| `BOOKING` | 예약 가능 시기·좌석·예약 경로·대기·티켓 접근 | 명절 기차 예매 시기, 대기알림 미수신 | 인증/결제 자체가 실패 원인이면 세부 코드 우선 |
| `TRANSPORT` | 교통 수단·탑승/충전·배차/수용량·노선 | 짐 때문에 택시 취소, 교통카드 종류 비교 | 지도 검색어 오류는 NAV_SEARCH |
| `NAV_SEARCH` | 앱 내 위치·상호명 검색·경로 정보 | 영문 상호명 검색 결과 없음 | 여러 앱 간 복사는 CONTEXT_SWITCH로 별도 표기 가능 |
| `CONTEXT_SWITCH` | 다수 앱·사이트에 같은 정보 이동·복사·중복 입력 | SNS→지도에서 한국어 명칭 다시 찾기 | 각 앱 내부 문제와 구분 |
| `LANGUAGE` | 사람과 대화·문자 안내·외국어 UI 이해 곤란 | 영어 가능한 식당/번역 지원 탐색 | 전화번호 인증과 혼동하지 않음 |
| `ONSITE_USABILITY` | 키오스크/웹·현장 안내 UI, 한국 이용 관행 | 숨겨진 해외 카드 선택, 음식 양 과다 주문 | 언어가 유일한 장애면 LANGUAGE |
| `OPERATING_INFO` | 서비스 운영 시각·휴무·행사 종료·상태의 불확실성 | 휴일 영업 우려, 예약 앱 장애 | 고객 앱 사용성 문제와 겹치면 직접 장애 우선 |
| `PREPARATION` | 입국·통신·결제·공항·짐 등 선행 준비 선택 | SIM/eSIM/카드·공식 입국 입력 안내 | 특정 예약 중 오류면 구체 코드 우선 |
| `CULTURE_DISCOVERY` | 새로운 문화·경험 선택 또는 흥미 확장 | 재방문 시 새로운 체험을 못 찾음 | '불편 발생'이라고 단정하기보다 발견의 미충족 수요 |
| `OTHER` | 미분류 | 신규 패턴을 그대로 보존 | 이유 기록 후 코드북 개정 |

## 4. 사례 판정 예시

- **팝업 예약에서 통신사 인증 화면이 나타남:** `IDENTITY / FIRSTHAND / FRICTION / BLOCKED` (실제 예약 완료 여부는 `UNKNOWN`일 수 있음). 한국 번호를 마련하면 예약이 해결된다는 말은 아님.
- **일본 관광객이 앱 인증이 필요하다고 들음:** `IDENTITY / QUESTION / CONCERN / UNKNOWN`. 당사자의 결제 실패로 세지 않음.
- **기차표를 예약하지 못했는데 예약 판매 시작 전이었음:** `BOOKING / QUESTION 또는 FIRSTHAND`를 본문에 따라 판정. ‘외국인이 차별로 예약 실패했다’고 확대 해석하지 않음.
- **해외 카드 사용이 원활했다는 후기:** `PAYMENT / FIRSTHAND / POSITIVE / SUCCEEDED`. 불편을 느낀 글만 많은 편향을 보완.
- **일본어 동영상 ‘여행에 유용한 앱 5가지’ 챕터:** 본문·실제 사용 장면을 확인하기 전까지 `source_register.csv`의 `VIDEO_CANDIDATE`로만 유지.
- **인증 번호가 없어 제3자 번호 입력을 추천하는 댓글:** 실제·법적 이용 가능성을 검증하기 전 사용자에게 제공할 해결책으로 채택하지 않음.

## 5. 2차 품질 기준

1. 원문을 다시 열어 **제목뿐 아니라 본문과 결과 업데이트**를 검토한다.
2. 영어/일본어/중국어 각각 최소 몇 개의 사건을 독립 분류하고 표준 해석을 맞춘다.
3. 2개 이상의 서로 다른 작성자가 같은 문제를 말한 경우에도 사건별 출처를 분리한다.
4. 관광객과 한국 거주 외국인의 장벽은 겉보기 비슷해도 이용 자격과 해결책이 다르므로 **분석 표본을 혼합하지 않는다**.
5. 원문 시각과 문제 발생 시각을 구분한다. 정책 변화·앱 업데이트 뒤 오래된 사례를 현재 상태로 주장하지 않는다.
6. 사용자 정보가 근거 없으면 `UNKNOWN`. 유추해 국가·연령·성별·체류자격을 입력하지 않는다.
