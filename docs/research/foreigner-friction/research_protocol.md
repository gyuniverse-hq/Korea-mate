# 조사 설계서 · KoreaMate 외국인 여행자 불편/기회 탐색 v1.0

작성: 2026-10-18. **탐색적 사례조사**이며 대표본 통계조사가 아니다.

## 1. 연구 질문

RQ1. 한국을 방문하기 전·중·후 외국인이 **어떤 서비스·준비·문화가 있다는 것 자체를 몰라** 시작하지 못하는가?

RQ2. 목표를 알고 시도한 뒤에는 어느 과업 단계에서 막히는가? **예약·현장 주문·결제·인증·교통·길찾기·사람과의 소통·운영정보**의 구체적인 실패·회피·완료 경로는 무엇인가?

RQ3. 기존 앱·웹·사람을 어떻게 조합해 문제를 해결했는가? KoreaMate의 **Service Connector·Travel Prepare·Help Me Now·My Korea·Plan B**가 도울 수 있는 부분은 어디인가?

RQ4. 이미 큰 불편 없이 여행하는 사람에게도 **개인화·새로운 K-Culture 발견·현재 인기 체험**의 부가가치가 있는가?

RQ5. 같은 현상을 실제 실패, 방문 전 우려, 보편적 정보 문의, 해결 성공으로 나누었을 때 제품 가설의 우선순위가 어떻게 달라지는가?

### 기존 연구에서 확인된 출발점

- 2025 외래관광객조사 전체 16,110명, 여가·친지 목적 분석 분모 12,339명. 정보 부족 및 만족 항목을 직접 관측했으나 **예약 성공·앱 전환·전화번호 오류·현장 행동 경로는 측정하지 않았다**.
- 탐색적 추천 성능은 개인화가 전체 인기순보다 과거 관광활동을 더 잘 예측한 것일 뿐, 앱 사용 전환 효과가 아니다.
- EDA v3의 정보 부족과 특정 활동 미참여의 관련성은 인과 효과가 아니다.
- 1330의 문의량은 **어떤 문제가 자주 상담되었는가**의 단서이지, 해당 문제를 겪는 외국인 전체 비율이나 해결 실패율이 아니다.

## 4. 추출 과정

1. **원천 등록:** 플랫폼, 원문 URL, 게시일, 언어, 확인한 깊이(검색결과/본문/댓글/영상/전사/설명)를 기록한다.
2. **사건 단위:** 한 사람의 한 목표와 한 막힌 단계(또는 완료 경험)를 1행으로 만든다. 한 후기의 다른 사건은 다른 case_id, 같은 source_id로 연결한다.
3. **단서와 확신:** 실제 겪은 일인지, 여행 전 걱정인지, 답변자의 제안인지, 홍보성 글인지 구분한다. 인과·법규·현행 서비스 조건은 검증 전 단정하지 않는다.
4. **장벽 코드 부여:** 어디서 막혔는지를 가장 세밀한 관측 가능한 단계로 기록한다. 여러 장벽이 있어도 `primary_barrier`는 직접적인 중단 지점 한 개.
5. **결과·대안:** 당사자의 성공/실패가 확인되지 않으면 `UNKNOWN`으로 둔다. 댓글의 해결 팁은 당사자 완료로 변환하지 않는다.
6. **중복/이상치:** 동일 URL·재게시·홍보 글은 원천 관계를 기록하고, 서로 다른 작성자의 경험을 합치지 않는다.
7. **현행 조건 검증:** 실제 제공자 공식 문서나 예약/결제 화면에서 서비스별 최신 정책·지역·시간을 확인한다. 확인 실패도 상태로 기록한다.

## 5. 품질 검수

- 최초 수집 47건은 **1인 코딩**. 코드북 기준표로 2차 검토자가 전체의 20% 이상을 무작위·다언어 층화 표본으로 독립 재분류한다.
- 가장 큰 의견 차이는 `QUESTION` 대 `FIRSTHAND`, `IDENTITY` 대 `BOOKING`, 실제 성공 여부다. 이유와 조정 기록을 남긴다.
- 사례 안의 지시사항·홍보·사기성 링크는 연구 지시로 취급하지 않는다.
- 날짜·URL·분류코드·출처 연결은 `scripts/validate_cases.py`로 검사한다.
- 2차 검수 전에는 ‘확인된 사용자 문제 발생률’, ‘대표 불편 순위’ 등 일반화한 문구 사용 금지.

## 6. 분석 순서

**A. 관측 범위 표:** 실제 경험/질문/성공을 분모로 따로 표시하고, 플랫폼·언어·여행 시기·대상 확인 비율을 기록한다.

**B. 사용자 과업 지도:** `goal → blocked_step → barrier → workaround → verified outcome` 관계를 묶는다. 무엇이 실제로 어려웠는지와 단순 정보 요청인지 구별한다.

**C. 기회 가설 맵:** `상황 → 필요한 정보·도구·공식 연결 → KoreaMate 지원 수준 → 확인 가능한 완료 조건`. 기능별 불편 건수로 즉시 순위를 매기지 않는다.

**D. 공식 자료와 삼각 검증(triangulation):** 방문 전 걱정(PRE), 방문 후 부족 정보(ACT), 관광상담(VOC), 사용자 경험(UGC), 신문화 관심(TREND)을 질문과 모집단별로 대조한다. 다른 모집단의 비율을 합산하지 않는다.

**E. 반례 수집:** 같은 앱·결제를 성공적으로 사용한 사례가 있는지, 서비스 정책이 바뀌었는지 확인하고 ‘항상 불가능’ 같은 표현을 제거한다.

**F. 사용자 과제:** 준비 항목을 몰랐던 사용자, 실제 예약·인증 중단, 지도/앱 전환 부담, 현장 소통, 관심 경험 탐색에서 일반 도구와 KoreaMate 시나리오를 비교한다. 5~8명은 탐색 용도로 충분할 수 있으나 효과 일반화 불가.

## 7. 연구 윤리와 정책

공개 게시글의 **연구 요약과 링크**만 저장한다. 이름·닉네임·연락처·IP·건강/정치 등 민감정보는 제외한다. 원문 전체, 영상 자막, 대량 댓글은 재배포하지 않는다. YouTube/Reddit 등의 수집·API·저작권·서비스 약관을 준수하며, 로그인/접근제한을 회피하지 않는다. 본인인증·결제 등 실제 규제를 회피하는 구현을 만들지 않는다.

## 8. 다음 반복에서 확인할 공백

- 실제 **서비스 사용 완료 이후** 재사용·다른 앱 전환·예약 취소 과정의 관측이 부족하다.
- 현재 시범의 영어 비중과 예약·인증 주제 비중이 높다. 언어·문화 이용·현장 소통·문화 발견의 원어 사례를 더 찾아야 한다.
- YouTube는 아직 본문·댓글 코딩 전이다. 영상의 상업적 제휴·클릭 유도 여부를 별도로 기록해야 한다.
- 1330의 **상담 유형별 원자료(공식 다운로드 제공 범위)**와 잠재 방한여행객의 문항별 표본·분모를 연결해야 한다.
- 커뮤니티 관측 뒤 2개 이상의 공식 서비스 이용조건 확인 및 실제 사용자 시연으로 원인을 구분해야 한다.
